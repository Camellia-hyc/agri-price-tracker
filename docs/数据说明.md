# 数据说明

> **本文档目的**:说明价格数据的规模、生成逻辑与文件结构。数据由两部分组成:**农业农村部官方真实行情**(Crawlee 爬虫 `scripts/crawl-pfsc.mjs` 每日抓取)与 **mock 补齐数据**(`scripts/generate-mock.mjs` 的价格模型填补真实数据缺口)。本文所有公式均出自这两个脚本。

## 2. 数据生成逻辑

脚本 `scripts/generate-mock.mjs` 使用 **mulberry32 伪随机数发生器 + 固定种子(20260917)**,因此每次运行生成的数据完全一致,便于演示与测试复现。

每条价格记录的计算公式:

```
价格 = 基准价 × 市场因子 × 季节波动 × 长期趋势 × 周末因子 × 随机噪声
```

各因子的含义与取值范围:

| 因子 | 取值 | 含义 |
|---|---|---|
| 基准价 `basePrice` | 2.2 ~ 68.0 | 每个产品固定的参考价,贴近真实市场水平 |
| 市场因子 `factor` | 0.92 ~ 1.15 | 市场间价差:一线城市偏高(上海 1.15、北京 1.08),中西部偏低(沈阳 0.92、西安 0.94) |
| 季节波动 `seasonal` | 幅度 ±5%~20% | 每个产品随机分配振幅 `amp` 与相位 `phase`,按正弦函数在 90 天内波动,让各产品曲线形态不同 |
| 长期趋势 `trend` | 90 天累计 −15% ~ +15% | 每个产品随机分配漂移率 `drift`,在 90 天内线性演进,制造上涨/下跌品种 |
| 周末因子 `weekend` | 1 或 1.012 | 周六周日采购需求略高,价格上浮 1.2% |
| 随机噪声 `noise` | ±3% | 每市场每产品每天的独立抖动 |

关键实现(节选):

```js
const withParams = products.map((p) => ({
  ...p,
  amp: 0.05 + rand() * 0.15, // 季节波动幅度 ±5%~20%
  phase: rand() * Math.PI * 2,
  drift: (rand() - 0.5) * 0.3, // 90 天累计涨跌幅 -15% ~ +15%
}))

// 今天往前推 90 天,数据始终是"最近 90 天"
const today = new Date()
const dates = []
for (let i = DAYS - 1; i >= 0; i--) {
  const d = new Date(today)
  d.setDate(d.getDate() - i)
  dates.push(fmtDate(d))
}

for (let di = 0; di < DAYS; di++) {
  const date = dates[di]
  // 周末采购需求略高
  const weekend = [0, 6].includes(new Date(date + "T00:00:00").getDay()) ? 1.012 : 1
  for (const p of withParams) {
    const seasonal = 1 + p.amp * Math.sin((2 * Math.PI * di) / DAYS + p.phase)
    const trend = 1 + (p.drift * di) / (DAYS - 1)
    for (const m of markets) {
      const noise = 1 + (rand() - 0.5) * 0.06
      const price =
        Math.round(p.basePrice * m.factor * seasonal * trend * weekend * noise * 100) / 100
      records.push({ productId: p.id, marketId: m.id, date, price })
    }
  }
}
```

最终价格四舍五入保留 2 位小数。

## 3. 数据文件结构

### 3.1 products.json(20 项,格式化输出)

```json
[
  {
    "id": "cabbage",
    "name": "大白菜",
    "category": "蔬菜",
    "basePrice": 2.2
  }
]
```

| 字段 | 说明 |
|---|---|
| id | 唯一标识(英文,作为关联键与 URL 参数) |
| name | 中文名 |
| category | 分类:蔬菜 / 水果 / 粮油 / 肉禽蛋 / 水产 |
| basePrice | 基准价,仅用于 mock 生成,前端展示不直接使用 |

### 3.2 markets.json(数量动态,2026-09-22 为 9 项,格式化输出)

```json
[
  {
    "id": "bj_xinfadi",
    "name": "北京新发地批发市场",
    "city": "北京",
    "region": "华北"
  }
]
```

> 生成脚本中市场还有一个 `factor` 字段(价格因子),但它**只参与生成**,写入 markets.json 前被剥离,前端 `Market` 类型中也不存在该字段。

### 3.3 prices.json(记录数动态,2026-09-22 为 16200 条,紧凑单行格式,约 1.3MB)

```json
[{"productId":"cabbage","marketId":"bj_xinfadi","date":"2026-06-20","price":2.77}, ...]
```

- `date` 为 `YYYY-MM-DD` 字符串,可直接按字典序比较大小;
- 记录按"日期 → 产品 → 市场"顺序排列,同一日期内先遍历产品再遍历市场;
- 采用紧凑格式(无缩进换行)以减小文件体积;products/markets 两文件数据量小,保留缩进便于人读。

## 4. 重新生成

### 4.1 全量 mock(不使用真实数据)

```bash
node scripts/generate-mock.mjs
```

脚本将覆盖 `public/mock/` 下三个文件,并打印统计信息(产品数 × 市场数 × 天数、日期范围)。**注意**:日期以运行当天的日期为终点,隔一段时间重新生成后,趋势页"近 90 天"区间会整体平移。注意此脚本会覆盖爬虫输出的市场列表(回到项目自定的 10 个市场)。

### 4.2 爬取官方真实数据(推荐,每日运行)

```bash
npm run crawl
```

Crawlee 爬虫抓取农业农村部**当日**行情,当日快照写入 `data/history/YYYY-MM-DD.json` 积累,再合并最近 90 天输出 `public/mock/markets.json` 与 `prices.json`。真实天数随每日运行增长,mock 补齐随之减少;跑满 90 天后数据 100% 真实。建议通过 cron / GitHub Actions 定时任务每日执行一次。

## 5. 真实数据接入(农业农村部官方爬虫)

项目当前采用 **Crawlee 离线爬虫** 接入官方数据:爬虫按项目数据结构生成 JSON 放进 `public/mock/`,前端 `src/services/api.ts` 零改动。数据源为农业农村部"全国农产品批发市场价格信息系统"(pfsc.agri.cn)。

### 5.1 爬取流程

1. **品种匹配**:调用 `GET /price_portal/sys-user-relation/getVarietiesTree` 拉取官方品种树(814 个品种),按产品名精确匹配 20 个目标品种得到 `varietyID`(西红柿官方 id=135、大白菜 77、猪肉 919 等);
2. **爬当日价格**:`POST /price_portal/index/getMarketReportPriceChart?marketIDs=&provinceCodes=&varietyID={id}`,20 个品种并发抓取。响应 `data` 字段为 **AES-256-CBC 密文**(key 内置于官网前端 JS,IV 取密文前 16 字符),脚本用 Node `crypto` 复刻解密,得到 `{date, x: 市场名数组, y: 价格数组}`(元/公斤);
3. **挑选 10 城市市场**:官方为"上报制",各品种当天有报价的市场不同(本次共 178 个)。脚本按「品牌同名优先 → 上报品种数最多」从北京/上海/广州/深圳/杭州/郑州/武汉/成都/西安/沈阳 10 个城市各挑 1 个代表市场;
4. **写快照**:当日真实记录以 `data/history/{日期}.json` 保存(日期、市场、记录);
5. **合并输出**:读取最近 90 天全部快照,生成 90 天 × 20 品种 × N 市场的完整记录网格——真实快照覆盖对应格子,其余格子用 mock 价格模型补齐(每格固定种子,市场增删不影响其他格子),输出 `markets.json` 与 `prices.json`。

### 5.2 已知局限

- **仅当日数据**:官方接口不提供历史回溯(已实测 reportDate/date/publishDate 等参数均无效),历史数据只能靠每日运行积累;
- **上报制市场**:各品种、各城市当天可能有价可报、也可能没有(本次小麦当天无报价、深圳当天无上报市场,脚本自动跳过),因此市场数、真实记录数每天略有波动;
- **行情口径**:官方为批发市场报送价,与零售价存在价差;猪肉等品类官方有多个细分品种(919"猪肉"、1492"猪肉(白条猪)"等),脚本自动选择当天市场数最多的候选。

### 5.3 未来演进:直接对接服务端 API(只改 api.ts)

若将来接入支持历史查询的行情 API(如新发地官网或其他商业数据源),只需修改 `src/services/api.ts`:页面层只依赖 `getProducts` / `getMarkets` / `getPrices` 的返回结构(`Product[]`、`Market[]`、`PriceRecord[]`),在函数内做字段映射并拼接查询参数即可,全部页面、图表、聚合逻辑零改动(详见《架构设计》)。

## 6. 已知说明

- `types/product.ts` 中 `Product` 声明了 `unit: string`(计量单位)字段,但当前 mock 数据未填充该字段,界面统一显示"元/公斤",该字段为后续接入真实数据预留。
- 日期字符串 `YYYY-MM-DD` 在全项目中按字符串比较(api.ts 过滤、页面取最大/最小日期),因此任何新数据源**必须保持此格式**,否则比较结果会出错。
