# 实验报告素材

> **本文档目的**:为课程设计 / 项目报告的撰写提供可直接组织成文的素材——背景与意义、开发环境、实现步骤、问题与解决方案、截图清单、总结与展望。内容全部来自项目实际开发过程,可按报告模板自行裁剪。

## 1. 项目背景与意义

农产品价格事关生产者收益与消费者支出,但价格信息分散在各地批发市场,存在**信息不对称**问题:同一农产品在不同市场价差可达 20% 以上,普通消费者难以比价;价格波动缺乏直观展示,从业者难以判断走势。

本项目构建"农价通"——农产品价格对比与趋势分析平台,解决两个核心问题:

1. **比价**:同一日期、不同市场之间横向对比,哪里最便宜一目了然;
2. **走势**:单一市场内纵向观察,近 7 天至近 1 年的涨跌与趋势可视化。

技术上,项目是一个前后端分离架构下的纯前端 SPA(演示数据本地化,接口层可平滑替换真实数据),实践了组件化开发、类型系统设计、构建优化与自动化部署等工程能力。

## 3. 实现步骤

项目按六个阶段推进,每个阶段产出可运行、可验证的结果:

**阶段一 · 项目初始化**
用 Vite 创建 React + TypeScript 工程;接入 Tailwind CSS v4 与 shadcn/ui(button / card / table);配置 `@` 路径别名指向 `src/`;搭建路由骨架(MainLayout 全局布局 + 首页 / 价格对比 / 趋势分析 / 404 四个路由)。

**阶段二 · 数据层与类型系统**
定义核心类型 `Product` / `Market` / `PriceRecord` / `PriceQuery`(集中在 `src/types/`);编写 `src/services/api.ts` 统一数据入口;编写 `scripts/generate-mock.mjs` 生成演示数据(20 产品 × 10 市场 × 90 天 = 18000 条)。

**阶段三 · 价格对比页**
产品多选(上限 3)、市场多选(上限 6)、日期选择器;分组柱状图(市场为 X 轴、产品为系列);价格明细表(每列最低绿 / 最高红高亮、均价行);封装通用 `EChart` 组件与共用 `ProductPicker` 组件。

**阶段四 · 趋势分析页**
市场单选、时间范围切换(7/30/90/365 天);统计卡片(最新价、区间涨跌、最高 / 最低 / 均价,红涨绿跌);多产品平滑折线图(Y 轴不从 0 起);区间聚合逻辑(日期 → 产品 → 价格两级 Map)。

**阶段五 · 首页与页面联动**
搜索框(产品 / 市场分组下拉建议);五大分类入口卡片;涨幅 / 跌幅榜 Top5(最新日 vs 前一日全市场均价);通过 URL 参数打通跳转(搜索、分类、异动榜 → 分析页)。

**阶段六 · 联调、优化与部署**
路由懒加载 + 构建分包优化(入口 chunk 748KB → 41KB);移动端响应式走查(汉堡菜单、表格横滚、图表自适应);SPA 深链接重定向配置;git 初始化与提交;Netlify 部署上线并验证全站路由与数据。

## 4. 遇到的问题与解决方案

| # | 问题 | 现象 / 原因 | 解决方案 |
|---|---|---|---|
| 1 | ECharts 5.6 类型声明冲突 | `BarSeriesOption` 等类型若与 `EChartsOption` 不同源导入,TS 编译报 zrender 类型声明冲突 | 所有 series 类型与 `EChartsOption` 从同一入口 `echarts` 同源导入 |
| 2 | 构建产物体积过大 | 初始单 chunk 748KB,超出警告阈值;ECharts 全量引入体积大 | ① 按需引入(仅注册 Bar/Line 等);② `React.lazy` 页面懒加载;③ `manualChunks` 拆 echarts / react 独立 chunk。优化后入口仅 41KB,图表页按需加载 |
| 3 | 切换筛选后图表残留旧系列 | ECharts `setOption` 默认为合并模式,产品数变少时旧系列不消失 | 调用 `setOption(option, { notMerge: true })` 整体替换 |
| 4 | 搜索下拉建议点击无效 | 点击建议项时 input 先触发 `blur` 收起下拉,`onClick` 未触发 | 建议项改用 `onMouseDown` 处理跳转(先于 blur 执行) |
| 5 | 直接刷新子路由返回 404 | 静态托管默认按文件路径查找,`/compare` 无对应文件 | 添加 `public/_redirects`(`/* /index.html 200`),由前端路由接管 |
| 6 | 1.4MB 价格数据被重复请求 | 每次查询都重新 fetch 全量 prices.json | api.ts 模块级缓存,全量下载一次后内存过滤 |
| 7 | Netlify 部署链接访客打不开(401) | Drop 首次生成的带哈希前缀链接是 draft 部署,仅登录者可见 | 在控制台执行 Promote to production 获得正式公开链接 |

其他工程防护措施(非故障,但值得写进报告):

- React 18 StrictMode 下 effect 会执行两次,数据加载统一使用 `cancelled` 标志,组件卸载后不再 setState,防止竞态;
- 日期统一为 `YYYY-MM-DD` 字符串,全项目按字典序比较,避免时区相关的 `Date` 解析问题(`shiftDate` 中拼接 `T00:00:00` 按本地时区解析);
- 全站配色遵循国内行情习惯"红涨绿跌",与通用图表库默认(红跌绿涨)相反,需在组件层显式指定。

## 6. 总结与展望

**已实现**:完整的三页面 SPA(搜索 / 比价 / 走势)、18000 条演示数据的生成与管理、ECharts 可视化(柱状图 / 折线图)、跨页面参数化跳转、移动端响应式、构建优化(懒加载 + 分包)与线上部署。项目体现了"数据层与展示层分离"的设计——未来接入真实数据只需修改 `api.ts` 一个文件。

**不足与展望**:

1. **真实数据接入**:当前为演示数据;已预留接口层,可对接新发地、农业农村部等公开行情,或第三方行情 API;
2. **功能增强**:价格预警(跌破/涨破阈值推送)、产品收藏、对比结果 CSV 导出;
3. **时间维度扩展**:当前数据覆盖 90 天,可扩展多年历史数据,并给折线图增加 dataZoom 缩放交互;
4. **性能**:若真实数据量大幅增长,可将"全量下载 + 内存过滤"改为服务端分页查询,页面层无需改动;
5. **工程化**:补充单元测试(聚合逻辑)与 CI/CD 自动部署。
